## Просмотр проекта

Сборка и установка зависимостей не требуются. Откройте `index.html` в современном браузере. Все страницы, стили, изображения и размерная сетка работают локально.

Для проверки отправки формы удобнее запустить локальный HTTP-сервер из папки проекта:

```bash
python3 -m http.server 8000
```

После этого откройте http://localhost:8000. На Windows вместо `python3` можно использовать `py`.

При просмотре непосредственно через `file://` поведение формы с GET-параметрами может зависеть от браузера. Для её проверки используйте HTTP-сервер или GitHub Pages.

## Технологии

- HTML5: семантические теги, таблицы, формы, `details`, `dialog`.
- CSS3: переменные, Flexbox, Grid, медиазапросы, состояния и позиционирование.
- Базовое БЭМ-именование классов.
- Минимальный JavaScript только для открытия/закрытия модального окна.
- Локальные авторские SVG-иллюстрации одежды; внешние шрифты и CDN не используются.
- Без CSS-фреймворков, npm-зависимостей, React/Vue и серверной части.

## Обязательные страницы

| Страница | Содержание |
| --- | --- |
| `index.html` | Hero-блок, преимущества, популярные товары, ссылки на каталог, заявку и контакты |
| `catalog.html` | Шесть карточек, четыре категории, статический макет фильтров и таблица сравнения |
| `product.html` | Изображение Field, описание, цена, характеристики, размерная сетка, кнопка заявки и модальное окно |
| `order.html` | Имя, e-mail, телефон, модель/размер, комментарий, согласие, способ получения и кнопка отправки |
| `contacts.html` | Контактная информация, ссылка на форму, FAQ, описание демонстрационного использования данных |

На каждой странице: `DOCTYPE`, `lang="ru"`, уникальные `title` и description, общие шапка, меню, подвал, один `main` и общий CSS. Основное меню одинаково на всех страницах. Текущая обязательная страница выделяется классом и `aria-current="page"`.

## Самостоятельные доработки

1. Собственная концепция FORMA: строгая типографика, акцентный красный цвет, каталожная композиция и локальные иллюстрации.
2. Пять дополнительных страниц товаров: ссылки ведут к соответствующей модели, а не к одной общей карточке. У каждой модели свой состав, цена, размеры и уход.
3. Дополнительная страница доставки/ухода и отдельный результат учебной формы.
4. Карточки с категориями, цветами, размерами и БЭМ-модификаторами для новинки, скидки и недоступной модели. У кепки отключена кнопка заявки; она отсутствует в форме.
5. Таблица сравнения трёх моделей, хлебные крошки, переходы по категориям и разделам, sticky-панель, кнопка «Наверх».
6. Форма с `fieldset`/`legend`, подсказками, проверкой e-mail/телефона, `required`, `autocomplete`, ограничением длины и очисткой. Модель и размер объединены в `select` с `optgroup`: неправильную пару выбрать нельзя без JavaScript.
7. Доступный нативный `dialog`: закрытие кнопкой, Escape и нажатием снаружи; браузер удерживает фокус. При отключённом JavaScript размерная таблица остаётся на странице.
8. FAQ на `details`/`summary`, skip-link, видимый фокус, `alt`, `caption`, `scope`, подписанные поля, поддержка `prefers-reduced-motion`.
9. Базовые медиазапросы для читаемости на небольших экранах и области горизонтального просмотра широких таблиц.
10. Документация: карта критериев, сценарий защиты, ответы на контрольные вопросы, инструкции запуска и публикации.

## Ограничения КР №1

- Фильтры намеренно статические и отключены; ссылки категорий работают как якоря. Это соответствует заданию, полноценная фильтрация относится к этапу JavaScript.
- Форма использует `GET` и переходит на `request-preview.html`. Это демонстрация HTML-валидации, а не реальная отправка продавцу. Значения включаются в URL и могут попадать в историю браузера и журналы хостинга. Вводите только тестовые данные.
- Страница результата не читает параметры, не проверяет факт отправки и не утверждает, что заявка принята.
- Нет корзины, оплаты, регистрации и хранения заявок.
- Контакты и условия магазина вымышлены.
- Итоговая оценка зависит также от понимания кода и защиты. Используйте [docs/DEFENSE.md](docs/DEFENSE.md) для подготовки.
