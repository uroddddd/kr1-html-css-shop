# Подготовка к защите

Не заучивайте только текст: откройте перечисленные файлы и найдите реализацию своими глазами.

## Демонстрация на 5–7 минут

1. Покажите репозиторий, `git log --oneline`, README и работающий GitHub Pages.
2. На главной объясните `header`, `nav`, один `main`, разделы `section`, карточки `article` и `footer`. Перейдите к преимуществам и популярным товарам по якорям.
3. Откройте каталог: покажите Grid, боковой `aside`, переходы по категориям, статические отключённые фильтры, бейджи и сравнение. Объясните, что фильтрация не реализована по ограничению КР №1.
4. Откройте Field и ещё один товар: у каждого собственная страница, состав, цена и размеры. В таблице покажите `caption`, `thead`, `tbody`, `th`, `td` и `scope`.
5. Откройте размерный `dialog`, закройте кнопкой, Escape и кликом по фону. Покажите короткий `js/main.js`: там только работа с модальным окном. Таблица также доступна без JS ниже на странице.
6. Откройте заявку. Попробуйте отправить пустую форму и некорректный e-mail. Затем заполните тестовыми данными: Тест, student@example.com, +7 (999) 123-45-67. Выберите Field / M и самовывоз, отметьте согласие. Объясните, что GET переводит на статическую страницу результата, а настоящего серверного заказа нет.
7. Покажите контакты, FAQ и дополнительную страницу доставки/ухода.
8. Откройте CSS и найдите переменные, Flexbox, Grid, hover, focus-visible, disabled, БЭМ и позиционирование. Пройдите несколько ссылок клавишей Tab.
9. Перечислите доработки и их пользу: правильные ссылки на товары, сравнение, допустимые пары размеров, доступность, FAQ и документация.

## Ключевые решения

- **Почему чистый HTML/CSS:** это предмет КР №1. Фреймворки и полноценная JS-интерактивность не нужны и не соответствовали бы цели работы.
- **Почему общий CSS:** единое оформление страниц без дублирования стилей в каждом HTML.
- **Почему шапка повторяется:** HTML-страницы самостоятельны; без сборщика или серверных шаблонов общая разметка присутствует в каждой. Это не дублирование CSS: стили централизованы.
- **Почему категории — якоря:** дают полезную навигацию в статическом каталоге без программной фильтрации.
- **Почему модель и размер вместе:** `optgroup` ограничивает допустимые сочетания средствами HTML. Не нужны зависимые селекты и JS.
- **Почему GET:** демонстрация отправки статической формы на Pages. POST требует обработчика. GET включает значения в URL, поэтому вводятся только тестовые данные.
- **Почему dialog:** браузер обеспечивает модальность, фокус и Escape. Минимальный JS только вызывает `showModal()` и `close()`.
- **Почему SVG:** оригинальные локальные изображения, небольшие файлы и чёткость при масштабировании. У каждого `img` есть alt, width и height.
- **Почему нет корзины:** задача — HTML/CSS-каталог с заявкой. Корзина и обработка заказов требуют следующего этапа разработки.

## Ответы на контрольные вопросы

1. **Зачем отдельный репозиторий?** Для независимой структуры, истории, ссылки на сдаваемую работу и публикации именно этой КР.
2. **Многостраничный и одностраничный сайт:** у многостраничного несколько самостоятельных HTML-документов и адресов. Одностраничный может объединять контент в одном документе; SPA отдельно меняет представления программно.
3. **Обязательные страницы:** index, catalog, product, order, contacts.
4. **Единая навигация:** сохраняет понятные переходы из любой страницы.
5. **Якорные ссылки:** переходят к элементу с конкретным id в текущем или другом документе.
6. **Семантические теги:** отражают смысл блоков для браузера, разработчика и вспомогательных технологий.
7. **Один main:** обозначает единственное основное содержимое документа; общая шапка и подвал находятся вне него.
8. **article:** самостоятельный материал, например карточка товара.
9. **Таблица:** структурированные данные, характеристики и сравнение; не используется для раскладки страницы.
10. **Форма:** собирает значения с именами name и передаёт их по указанному action/method. В этом проекте это учебный сценарий.
11. **CSS-модалка и dialog:** CSS-модалка управляется селекторами и состоянием, а dialog имеет нативную семантику и при showModal() блокирует фон. CSS-модалке обычно сложнее обеспечить клавиатурное поведение.
12. **CSS-переменные:** единые значения цветов/отступов, которые повторно используются через var().
13. **hover и focus-visible:** hover показывает наведение мыши; focus-visible помогает видеть элемент при управлении клавиатурой.
14. **Flexbox:** удобен для одного направления, например горизонтального меню и группы кнопок.
15. **Grid:** удобен для строк и столбцов одновременно, например каталога с боковой панелью.
16. **БЭМ:** Блок, Элемент, Модификатор — способ именования классов по роли.
17. **Блок и элемент:** блок самостоятельный (`product-card`); элемент его часть (`product-card__title`).
18. **Элемент и модификатор:** элемент обозначает часть, модификатор — вариант или состояние (`product-card--discount`).
19. **Почему не стили по id:** селекторы с id имеют высокую специфичность и плохо переиспользуются. id здесь служат якорям и связям label/aria, классы — оформлению.
20. **Что в README:** название, тема КР, описание, структура, технологии, Pages, запуск, страницы, доработки, ФИО и группа.
21. **Что доработано:** отдельные страницы всех моделей, доставка, результат формы, сравнение, FAQ, хлебные крошки, размерная сетка, доступность, состояния карточек.
22. **Почему это улучшает проект:** помогает выбирать одежду по данным, предотвращает неверную пару размера и модели, сохраняет доступность с клавиатуры и показывает честный сценарий заявки.

## Где искать в CSS

Используйте поиск по именам: `:root`, `.site-nav__list`, `.catalog-layout`, `.product-grid`, `.product-card__badge`, `.order-form__input`, `.data-table`, `.size-dialog`, `.back-top`, `:focus-visible`, `prefers-reduced-motion`.

## Что не утверждать на защите

- Что форма отправляет заказ продавцу: сервера нет.
- Что фильтры программно фильтруют товары: они статические.
- Что сайт опубликован, пока публичная ссылка не проверена.
- Что максимальная оценка гарантирована: понимание кода оценивает преподаватель.
